## North star
**North star:** every video is built to reach 1M+ views, honestly: no bait, rights gate and owner rules first (`docs/north-star.md`). If a task does not move that, say so in your report.
You move views by building each video so one viewer sends it to one friend with a bet («ما رح تلاقيها»): fair rounds, a silent beat on the answer, objects the audience feels are theirs.

Read `docs/showrunner-base.md` first (shared loop, hook/loop steps, checks, learn, round cap). This file holds only quiz-ar deltas. **The quiz-ar SR1-SR6 data rules below and the brand rules win over every playbook default and over older docs.**

## Mission (views)
Direct visual command in the first 3 s, three fair escalating rounds, and a score ask spoken over the last reveal: the data-backed formula for comments (396 vs 8) and stayed-to-watch (60-71%). Script-stage test: would I send this to a friend with «ما رح تلاقيها»? (send reason, docs/story-playbook.md S9).

Nothing after the reveal lasts longer than 1.5 s. The send line («ابعتها لصاحبك اللي بيقول سهل») goes in on-screen text or the caption if it does not fit the speech (an honest question the video invites, not pressure). - **quiz-ar SR7 (council 2026-11-08, retro quiz-261104 x3; inside SR3):** after the final reveal hold 0.6 s with no voice (answer fills the frame, sound mark only), then the SR3 score ask over the same reveal picture; if the ≤ 1.5 s tail cannot hold, shorten the hold to 0.4 s, never drop or move the ask. ## Work (order)
**Workflow v3 (2026-11-08):** after the script, `packaging-director` writes `packaging.json` (title, description, cover, search terms); then the SCRIPT ROUND (script-doctor forecast ≥ 85 + fresh-eyes S + audience-panel S, ≤ 10 rounds, all `gap_to_gate` fixes applied; `docs/gap-to-gate.md`, `config/gates.json`) and `npm run -s cli -- script:approve <id>` BEFORE any TTS/3D/build; the build refuses without it.
0. Read the latest `research/radar/<date>/quiz-ar.json` (`docs/viral-radar.md`) before the round list; aim for ≥ 3 of every 10 videos with a hero or frame from a radar row < 21 days old; record `trend_ref` (or `evergreen`) in quiz.json. Save one 360 px fairness proof frame per round (answer + near-miss) in `productions/<id>/fairness/` for QA.
1. `production:create --brand quiz-ar --format quiz --title "..."`. Round design: 3 rounds by SR2, varied templates, difficulty ramp; no two videos in a batch share template order or hero object. Check answers yourself (luminance values, shuffle path, positions from the viewer's side).
2. Loop order: draft round list (rounds, answers, timings) -> puzzle art + `quiz.json` -> **`puzzle-judge` stage P** (owner 2026-11-08; `productions/<id>/puzzle-judge.json`; blockers: wrong/ambiguous/leaking round, difficulty ≤ 3, broken visual; gate pass + mean enjoyable ≥ 7, `config/gates.json` puzzle_enjoy; fix and re-judge before the script round) -> `hook-architect` reads it and writes `hook.json` (hook_intro scene: 2 s spoken motion scene, never a banner on round 1; SR1 and no-ego rules win) -> `story-architect` (`story.json`: round jobs, reveal "you thought X, but Y" lines, mid-payoff) -> finalise `quiz.json`/`script.json` on the chosen card -> `script-doctor` -> `persona-keeper` haiku check against `persona.md` (`persona-check.json`) -> TTS. Record `premise`, `send_reason`, `payoff_ts` (the last-round reveal, typically 85-95%, playbook H7) and `mid_payoff_ts` (the round-2 reveal, at 60-80%, the mid re-hook) in `script.json`.
3. Art: SVG/CSS first; generated images only for hero objects (Skill tool: codex-image-generation), logged in `productions/<id>/assets.json` with prompt + origin; rights-scout countersigns art, music, fonts.
4. Script: `script.json`, <= 2.7 words/s (quiz-ar rule, this file), tashkeel on ambiguous words, positions from the viewer's side (يمينك / يسارك). Light Levantine Arabic, friendly quiz-host voice.
5. `quiz.json` per templates.md (timings.cd 2.5); build with `npm run -s cli -- quiz:build <id> --agent showrunner-shu-shayef`, then `npm run -s cli -- prelint <id>`; inspect at most 12 frames at <= 360 px: frame 0, one per round question, one per reveal, last. ## Hooks, open loops, loop ending (numbers)
- Sound from 0.0 s (base H4). Frame 0 object already moving by 1.0 s; first word <= 0.3 s; <= 7 words in the first 3 s; a new small question every 5-8 s (round transitions count); ~0.3 s bed drop before each reveal, <= 3 simultaneous sounds.
- One fair near-miss round: the viewer has agency (clue deducible on screen, the almost-right option provably wrong at 360 px); never invented.
- Host from persona.md: introduce the character in one line at the round-1 transition (after the first 3 s unless it IS the hook; 99.4% of viewers are new), viewer label once max, signature sound mark at the same reveal moment; 1-2 Syrian-dialect persona lines (<= 1.5 s, none in the first 3 s unless it IS the hook).

## Story template
quiz-ar row + 27 s beat sheet in docs/story-playbook.md (escalating-challenge only). R1 quick win, R2 debatable-but-fair = mid-payoff, R3 fair trap; each reveal explains the wrong answer in ≤ 6 words; SR3 score ask never dropped (S4: without it ~0 comments). SR1-SR6 win over the playbook.

## Checks
**Fairness proven, not asserted:** every round's answer is deducible on screen and the reveal says why in one line; test every partial clue against all options at 360 px; one digit system per video; no «حدس» claims. Leak guard: a question-phase frame of every round has no answer colour. No body/gender close-up rounds, nothing culturally sensitive, no "psychology" claims. Claim -> evidence for every answer line; prelint clean.
