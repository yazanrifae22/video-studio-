# Tech Made Simple: channel bible (owner: Ada, tech director)

Last updated 2026-10-20. Keep this file short. It holds what every new tech video must stay consistent with, or deliberately differ from.

## Palette (engine theme `tech`)
bg `#070A12` · ink `#EEF3FF` · muted `#8B9BC0` · accent `#5B8CFF` · accent2 / "good" `#3DF2C2` · warn / "attention" `#FFB547` · danger `#FF5C7A` · panel `#0F172B` · line `#24324F` · violet `#B18CFF` · gold (tokens/coins) `#FFC94D`.
Meaning is stable: mint = success / correct path, amber = the thing to watch, red = failure / error, violet = keywords in code.

## Voice and sound
Charon, `maxPause` 0.26, `tech-focus` bed at −19 dB. One TTS take per video. Write numbers as words when they will be spoken ("one thirty", "four twenty-nine"). In custom-scene `T()`, hyphenated words normalise without the hyphen (`thirtysix`, `twentynine`, `retryafter`).

## Glossary (on-screen wording)
KV colours: key = blue, value = violet, query/new token = amber, redone work = red, cache = mint, memory = gold. Infra colours: reverse proxy = blue, load balancer = gold, API gateway = violet. JWT colours: header = red, payload = violet, signature = blue. OAuth colours: code = amber, access token = gold, ID token = blue, Google path = mint, scopes = violet.

DNS colours: question/resolver = blue, cache hit/answer = mint, referral = violet, root = amber, .com = gold, Google NS = mint, miss = red.

## Accuracy rules that came out of fact-checks
- Don't name a tool as the culprit when its docs say it handles the case (cron avoids DST double runs).
- Defaults come with their scope on screen ("account default · most AWS Regions"; "max_turns = 10" is an example value).
- Security demos: never show a real token, key or signature; build demo tokens from made-up claims and redact the signature. Don't tell viewers to paste tokens into websites.
- Prefer "often" or "many" over "always" or "never" unless a spec says MUST.
- Real incidents: every fact from the vendor's own post-incident summary plus ≥ 1 independent outlet; illustrative IPs from RFC 5737 (203.0.113.x); no claims about what happened after the summary.
- DNS facts: measure TTLs and referrals live (`nslookup -debug -type=NS com. 198.41.0.4`, then the .com server, then the authoritative one) and put "measured <date>" on screen; root instance counts change daily (root-servers.org), so date them.
- LLM videos: never say the model "has no plan" (Anthropic 2025 shows planning ahead); odds on screen are labelled "illustrative" unless measured; token splits come from a real tiktoken run.

Float colours: literal 0.3 in code = blue, the sum 0.1+0.2 = amber, exact value / fixes = mint, false = red, bits = violet, 64-bit / IEEE = gold. Mono font has ligatures (=== renders as one bar): custom scenes must set font-variant-ligatures:none.

Password colours: password = amber, hash = blue, salt = gold, hash machine = violet, match/fix = mint, attacker = red. Demo hashes are real SHA-256 outputs; say 'demo' on screen and never recommend plain SHA-256 for passwords.

QR colours: data codewords = blue, error-correction 'clues' = mint, wrecked = red, finders/zigzag = amber, scanner = mint. Every QR on screen must be a real, decoder-tested code of a reserved domain (example.com), never a decorative fake. Scope failures to 'our scanner' (zxing-cpp); readers differ.

Emoji/Unicode colours: person code points / their units = blue, ZWJ joiners = amber, limit/dropped/broken = red, graphemes/fix = mint, counts = gold, Python = violet. Measure every length with the real runtimes (measure.cjs in the production) and name them on screen (Chrome 155, Node 24); a lone surrogate 'often' shows as � (scope it).
